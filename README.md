# Support AI Agent Framework (L1/L2)

A modular, multi-agent framework for technical ticket resolution, designed with stateful orchestration (LangGraph), strict data isolation (Multi-Tenancy), and read-only evidence collection (MCP).

## 🚀 Key Features

*   **Multi-Agent Orchestration**: Specialized agents for Classification, Scoping, Evidence Collection, Hypothesis Generation, and Planning.
*   **Security First**: Read-only tool execution via MCP, strict tenant isolation in Database and Vector Store.
*   **Modular Inputs**: Supports Webhooks (Push) and Pollers (Pull) for ingestion.
*   **Evidence-Driven**: All reasoning is grounded in immutable evidence snapshots.

## 🛠️ Project Structure

## ⚡ Quick Start

### Prerequisites
- Python 3.12+
- PostgreSQL
- Qdrant (or Docker equivalent)
- `uv` (Package Manager)

### Installation

1.  **Initialize Environment**:
    ```bash
    uv sync
    ```

2.  **Configuration**:
    Create a `.env` file based on your environment:
    ```env
    DB_HOST=localhost
    DB_USER=postgres
    DB_PASS=password
    DB_NAME=support_agent_db
    QDRANT_URL=http://localhost:6333
    OPENAI_API_KEY=sk-your-key-here
    ```

3.  **Database Setup**:
    Run migrations:
    ```bash
    uv run alembic upgrade head
    ```

### Usage

**Run a Test Ticket (CLI Mode)**:
Simulate a ticket flow through the agent graph:
```bash
uv run python src/main.py test
```

**Start the Webhook API**:
```bash
uv run uvicorn src.ingestion.api:app --reload
```

## 🏗️ Architecture

The system follows a **Triage Pipeline**:
1.  **Ingest/Normalize**: Convert raw inputs to standard `Ticket`.
2.  **Context & Classify**: Fetch customer context and determine domain.
3.  **Scope**: Identify involved components.
4.  **Collect Evidence**: specific tools probe the components.
5.  **Enrich**: Map findings to known issues/KB.
6.  **Desgin**: Formulate Hypotheses and a Safe Plan.
7.  **Respond**: Format output for human review.
