# API Integration Guide

The Support AI Agent exposes a robust, asynchronous REST API built with FastAPI designed to handle long-running reasoning processes without hitting HTTP timeouts. 

This document outlines the **Asynchronous Job Pattern** used for the ingestion and monitoring of tickets.

## The Asynchronous Job Pattern

Due to the complex nature of technical investigation, an agent run can take anywhere from 1 to 15 minutes. To provide a seamless integration with frontends (like React, Streamlit, etc.) and third-party Webhook providers (Jira, ServiceNow), the API immediately acknowledges the receipt of the ticket and processes the LangGraph workflow in a background `asyncio` task.

### 1. Ingesting a Ticket (POST)

When a ticket is generated in your external system or UI, send a POST request with the incident payload.

**Endpoint:** `POST /api/v1/webhook/{source_id}`

**Headers:**
- `X-Customer-ID`: (Required) The ID of the tenant to ensure strict data isolation.

**Payload body (Example):**
```json
{
  "id": "INC001234",
  "mode": "incident",
  "severity": "high",
  "text": "User reporting they cannot reach 172.27.0.0/24 through the SD-WAN firewall fgt_casa.",
  "source": "servicenow"
}
```

**Response (`202 Accepted`):**
```json
{
  "status": "accepted",
  "message": "Ticket ingested. Processing launched in background.",
  "ticket_id": "INC001234",
  "job_id": "7864f7b2-1a2c-4e56-b9a1-0f4b3c2d1e5f"
}
```
*Save the `job_id` returned in this response. It acts as your tracking number.*

---

### 2. Polling for Status (GET)

A frontend application should poll this endpoint every 5-10 seconds to check if the agent has finished diagnosing the ticket.

**Endpoint:** `GET /api/v1/jobs/{job_id}`

**Response while running (`200 OK`):**
```json
{
  "job_id": "7864f7b2-1a2c-4e56-b9a1-0f4b3c2d1e5f",
  "status": "running",
  "ticket_id": "INC001234"
}
```

**Response when finished (`200 OK`):**
```json
{
  "job_id": "7864f7b2-1a2c-4e56-b9a1-0f4b3c2d1e5f",
  "status": "completed",
  "ticket_id": "INC001234"
}
```

---

### 3. Retrieving the Final Report (GET)

Once the job status reads `completed`, the Frontend can retrieve the detailed Engineering Report generated by the Response Agent.

**Endpoint:** `GET /api/v1/tickets/{ticket_id}/report`

**Response (`200 OK`):**
```json
{
  "ticket_id": "INC001234",
  "job_id": "7864f7b2-1a2c-4e56-b9a1-0f4b3c2d1e5f",
  "status": "completed",
  "report": "# Engineering Report\n\n## 1. Context\n... (Full Markdown text) ..."
}
```

## Running the Full Stack (API + UI)

The project includes a reference **Streamlit UI** (`streamlit_app.py`) that implements the polling logic described above. It provides a visual interface to select tenants, submit technical issues, track the agent's progress via a progress bar, and render the final Engineering Report.

### 1. Start the API Server

The API uses a Lifespan context manager to load the MCP tools and connect to your servers *before* accepting requests. Start it using `uvicorn`:

```bash
uv run uvicorn src.ingestion.api:app --reload
```

By default, the server will expose Swagger UI documentation at `http://localhost:8000/docs`.

### 2. Start the Streamlit UI

In a separate terminal, launch the frontend:

```bash
uv run streamlit run streamlit_app.py
```

The UI will be available at `http://localhost:8501`. It will connect to the API on port 8000 by default.
