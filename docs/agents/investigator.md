# Investigator Agent

## Description
The Investigator Agent is responsible for verifying specific hypotheses generated by the Hypothesis Agent. It selects the highest-priority "proposed" hypothesis, formulates a verification plan, searches for appropriate tools, and executes them to gather evidence.

## Role in Graph
- **Node Name:** `investigator_agent`
- **Upstream:** `supervisor` (routed when a hypothesis needs verification)
- **Downstream:** `enricher_agent` (to process the newly collected evidence)

## Inputs
- `state["hypotheses"]`: List of hypotheses. The agent targets the highest-ranked one with status `proposed`.
- `state["ticket"]`: Ticket details for context.
- `state["components"]`: List of identified components to scope tool arguments.

## Outputs
- `state["hypotheses"]`: Updates the status of the target hypothesis to `verifying`.
- `state["evidence_refs"]`: Appends new evidence snapshots collected from tool executions.

## Prompts

### 1. Verification Plan
**System:** "You are an expert Network Troubleshooter."
**Goal:** Identify the most effective tool execution to prove/disprove the hypothesis.
**Prompt Structure:**
```text
Context:
Ticket: {ticket_text}
Hypothesis: {hypothesis_summary}
Components: {component_ids}

Task: Identify the SINGLE most effective diagnostic tool execution to verify or disprove this hypothesis.
Focus on "proving" the hypothesis.

Return a JSON object with:
- "search_query": Keywords to search for tools (e.g. "fortigate firewall policy lookup")
- "reasoning": Why this tool?
```

### 2. Tool Selection
**System:** "You are an expert Automation Engineer."
**Goal:** Select the specific tool from the registry search results and configure its arguments.
**Prompt Structure:**
```text
Appliable Tools:
{tool_list_json}

Hypothesis: {hypothesis_summary}
Components: {components_json}

Task: Select the best tool and configure arguments.
GUIDELINES:
1. CRITICAL: Use Component IDs for 'device', 'target', 'host' arguments.
2. ANTI-HALLUCINATION: If a mandatory parameter is missing from the context, DO NOT INVENT IT.
3. CONTEXT CHECK: Look for parameter values in 'Facts' and 'Evidence'.

Return JSON:
{
    "tool_name": "name",
    "arguments": { "arg": "value" }
}
```

## Key Logic & Interactions

### 1. Smart Argument Sanitization (Role-Based)
The agent applies strict logic to prevent "Device NOT FOUND" errors:
- **`device` Argument:** Only assigned if the component is an **EXECUTOR** (Firewall, Router, Switch, Server).
- **`target`/`destination` Argument:** If the component is a **TARGET** (Subnet, IP, URL), it is used here instead of `device`.
- **Auto-Correction:** If the LLM incorrectly assigns a Subnet ID to `device`, the agent intercepts and corrects it (blocks or moves it to `target`).

### Tool Search & Limitations
The agent uses `CapabilityRegistry.search_tools(query)` to find relevant tools.
- **Mechanism:** The search is currently a **simple keyword match** against tool names and descriptions.
- **Limitation:** Natural language queries like *"FortiGate diagnose debug flow policy lookup 192.168.241.0 https aws"* often fail because no single tool contains all those words.
- **Fallback:** If no tools are found, the agent falls back to a generic `ping` search.

> **Note:** The warning `Investigator: No tools found for query '...'` indicates that the LLM generated a search query that was too specific or verbose for the current search implementation.

### Evidence Propagation
After executing a tool, the agent:
1.  Saves the raw output to the `EvidenceStore`.
2.  Creates an `EvidenceSnapshot`.
3.  **Crucially**, appends this snapshot to `state["evidence_refs"]` so that the `Enricher` and `Hypothesis` agents can see the new data.

### Interaction Flow
1.  **Selection:** Picks the top `proposed` hypothesis.
2.  **Planning:** asks LLM *what* to do (output: search query).
3.  **Search:** Queries the `CapabilityRegistry`.
4.  **Configuration:** Asks LLM *how* to do it (output: tool name + args).
5.  **Execution:** Runs the tool and saves evidence.
6.  **State Update:** Marks hypothesis as `verifying` and returns control to the graph.
